# Firestore Eloquent 4.0

Firestore Eloquent gives Laravel applications an Eloquent-style API for Google Cloud Firestore. Version 4.0 focuses on secure server authentication, native Laravel authentication, faster pagination and relationships, bounded-memory processing, bulk writes, and IDE-discoverable model methods.

## Highlights

- Familiar model queries: `where()`, `orderBy()`, `find()`, `first()`, aggregates, and more
- Laravel-style `FS::collection()` query builder for model-free access
- Native Laravel `Auth` support through the `firestore` user provider
- Numbered, simple, and cursor pagination using Laravel paginator classes
- `hasOne`, `hasMany`, and `belongsTo` relationships with batched eager loading
- Cursor-backed `chunk()` and `lazy()` processing for large collections
- Batched `updateMany()` commits of up to 500 writes per request
- Service-account and Application Default Credentials authentication
- Firestore emulator support
- Concrete static model methods for Intelephense and other PHP language servers

:::tip[Choosing pagination]
Use [cursor pagination](./guide/pagination.mdx#cursor-pagination-recommended) for large or frequently accessed collections. Numbered pagination is convenient, but deep Firestore offsets become slower and cost more document reads.
:::

## What this package is not

Firestore is a document database, so Firestore Eloquent is not a drop-in replacement for every SQL Eloquent feature. It does not provide joins, migrations, or every Eloquent query method. See [Limitations](./limitations.mdx) before designing a data model.

# Authentication

Version 4.0 integrates Firestore with Laravel's normal authentication guards. The older `FAuth` API remains available for backward compatibility.

## Create a user model

```bash
php artisan make:fmodel User --collection=users
```

Configure fields used by registration and login:

```php
class User extends FModel
{
    protected $collection = 'users';

    protected $fillable = [
        'id', 'name', 'email', 'password',
    ];

    protected $required = ['email', 'password'];
    protected $hidden = ['password', 'remember_token'];
}
```

Store passwords with Laravel's `Hash::make()`. Never store plain-text passwords.

The `password` field should be fillable if Laravel may automatically rehash it. The remember token is persisted separately and does not need to be fillable.

## Configure Laravel

Set the provider in `config/auth.php`:

```php
'guards' => [
    'web' => [
        'driver' => 'session',
        'provider' => 'users',
    ],
],

'providers' => [
    'users' => [
        'driver' => 'firestore',
        'model' => App\FModels\User::class,
    ],
],
```

To use a non-standard password field, add `password_field` to the provider and match `firebase.auth.password_field`.

## Register a user

```php
use App\FModels\User;
use Illuminate\Support\Facades\Hash;

$user = User::create([
    'name' => $request->string('name')->toString(),
    'email' => $request->string('email')->toString(),
    'password' => Hash::make($request->string('password')->toString()),
]);
```

Enforce unique email addresses in application logic and Firestore rules; Firestore Eloquent does not provide a SQL-style unique constraint.

## Log in

```php
namespace App\Http\Controllers;

use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;

class LoginController extends Controller
{
    public function authenticate(Request $request): RedirectResponse
    {
        $credentials = $request->validate([
            'email' => ['required', 'email'],
            'password' => ['required'],
        ]);

        if (Auth::attempt($credentials, remember: $request->boolean('remember'))) {
            $request->session()->regenerate();
            return redirect()->intended(route('dashboard'));
        }

        return back()->withErrors([
            'email' => 'The provided credentials do not match our records.',
        ])->onlyInput('email');
    }
}
```

The provider supports Laravel's standard APIs:

```php
Auth::attempt($credentials);
Auth::user();
Auth::id();
Auth::check();
Auth::guest();
Auth::login($user);
Auth::loginUsingId($id);
Auth::once($credentials);
Auth::viaRemember();
Auth::guard('web');
```

## Logging Out

```php
Auth::logout();
$request->session()->invalidate();
$request->session()->regenerateToken();

return redirect('/');
```

## Protect routes

Use Laravel's built-in middleware with the native provider:

```php
Route::middleware('auth')->group(function () {
    Route::get('/dashboard', DashboardController::class);
});

Route::middleware('guest')->group(function () {
    Route::get('/login', LoginController::class);
});
```

HTTP Basic Auth methods such as `Auth::basic()` use the configured provider too. Use them only over HTTPS.

## Legacy FAuth

Existing applications may continue using:

```php
use Roddy\FirestoreEloquent\Auth\FAuth;

FAuth::attempt(['email' => $email, 'password' => $password]);
FAuth::user();
FAuth::id();
FAuth::check();
FAuth::logout();

fauth()->user();
```

`FAuth` uses the `auth_model`, `auth_url`, and `guest_url` settings in `config/firebase.php`. New applications should prefer Laravel's provider and built-in middleware.
